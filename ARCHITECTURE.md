# Архитектура

## Этап A

- Next.js App Router и React Server Components для страниц.
- TypeScript в строгом режиме.
- Tailwind CSS 4 и локальная дизайн-система в `app/globals.css`.
- Базовый компонент `Button` по схеме shadcn/ui с Radix Slot.
- Lucide для иконок.
- `lib/business.ts` содержит публичные тариф и контакты. Все цены на страницах и в калькуляторе берутся из этих констант.
- Для сборки в этой Windows-среде задан один рабочий процесс генерации страниц (`experimental.cpus: 1`) и отдельный каталог `.next-single`. Это обходит локальные ошибки записи при параллельной генерации.
- Клиентские компоненты изолированы: `site-header.tsx`, `price-calculator.tsx`, `booking-form.tsx`.
- Форма не использует API и хранит введённые значения только в памяти браузера. После проверки она прямо сообщает, что заявка не отправлена.

## Структура

- `app/` — маршруты, метаданные, стили, sitemap и robots.
- `components/` — навигация, футер, интерактивные компоненты и UI.
- `lib/` — бизнес-константы и утилиты.

## Следующие этапы

На этапе B добавятся PostgreSQL, Prisma, серверная валидация и настоящее сохранение заявок. Сервер будет пересчитывать стоимость, фиксировать тариф на момент заявки и возвращать успех только после записи в базу. До запуска обработки персональных данных требуется завершить юридические тексты и определить параметры хранения в РФ.

На этапе C защищённая авторизацией админ-панель позволит просматривать заявки и управлять тарифом. На этапе D подтверждённые интервалы и ручные блокировки будут защищены от пересечений транзакциями и ограничением PostgreSQL. На этапе E уведомления Telegram будут отправляться через серверную очередь с повторными попытками. На этапе F готовятся Docker Compose, Caddy, резервное копирование и production-настройки VPS в России.

`/admin` сейчас намеренно возвращает 404: публичной административной информации нет. База данных, авторизация и Telegram Bot API ещё не подключены.
